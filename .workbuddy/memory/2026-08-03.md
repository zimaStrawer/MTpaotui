## 美团跑腿原型（MTpaotui）移动端图片性能优化

背景：Vercel 部署后手机端图片加载卡顿。调查结论：主因是 14MB 未压缩 PNG/JPG + 无缓存头 + 无懒加载，SVG 仅 184KB 非瓶颈（用户决定 SVG 优化暂缓）。

已完成（两轮）：
- 28 张 PNG/JPG → WebP（scripts/convert-webp.mjs，sharp q80）：14.3MB→1.6MB
- 19 张超大 WebP 按 2x 显示宽原地降采样（scripts/resize-webp.mjs）：1529KB→343KB，LCP hero 图 225KB→17KB
- vercel.json：/assets/* immutable 长缓存 + index.html no-cache
- router.tsx：5 页面 React.lazy + Suspense，主 bundle 505KB→304KB
- img 属性：首屏图 fetchPriority="high"+decoding+宽高；非首屏图 loading="lazy"（HeroPromo/MapPreview/OrderMap/TrackingMap/ItemProofCard/CompletedOrderView/CourierCard/VolumeCard/TypeSummaryCard/AdditionalServices/ShowcaseLayout）
- main.tsx 动态 preload 两张 hero mascot（hash 文件名无法写死 index.html）
- 清理 31 个未引用残留图（保留 showcase/github-repository-qr.png），卸载 svgo

结果：dist 12MB → 1.0MB（-92%）。

注意点：
- 项目中多图为雪碧图/overflow 裁剪（courier-avatar、extra-service-icons、courier-scooter），降采样目标宽需按「渲染出的整图宽」而非可见区域计算
- QR 码不转 WebP（变大且可能影响识别）
- macOS BSD sed 正则易踩坑，批量替换用 perl

待办（用户暂缓）：SVG 优化（SVGO、3 个 feGaussianBlur glow 图、assetsInlineLimit）；Lighthouse mobile 实测验证 LCP<2.5s。
